# podcast-move-check 中文说明

在播客更换托管平台前，对比两份本地 RSS 2.0 快照，检查旧剧集的身份和编号是否保留。
整个检查离线进行，不下载音频，不调用服务，不修改订阅或源文件。需要 Python 3.11 以上；
安装时会增加小型 XML 安全解析依赖 `defusedxml==0.7.1`，实际运行不联网。

克隆仓库、创建虚拟环境后，使用该环境的 Python 执行 `python -m pip install .`。

```sh
podcast-move-check old.xml proposed.xml --json
python examples/demo.py .demo
```

它区分 GUID 保留时正常的媒体地址迁移、相同媒体地址下的 GUID 改写，以及没有可靠证据
确认对应关系的旧剧集。不会按标题或位置猜测匹配。报告只列两份快照中的条目序号、问题码
和计数，不复制订阅 URL、GUID 或标题。新增目标条目不阻断；旧剧集找不到对应项会阻断。

旧季号、集号、类型和已有的 Podcasting 2.0 节目 GUID 变动也会阻断。
媒体元信息、日期等问题默认警告，`--strict` 会把警告也作为失败。
无 GUID 的旧源默认失败；`--allow-enclosure-identity` 显式允许依靠两端都唯一且完全相同的
媒体地址保留旧身份，仍给出警告，且不代表满足任何平台的完整要求。

退出码：`0` 快照通过所选连续性规则；`1` 检查完成但存在阻断项；`2` 输入不支持或检查未完成。
默认每个文件不超过 16 MiB、50,000 剧集、200,000 元素和 64 层深度。只接受 UTF-8 RSS 2.0；
DTD、实体声明和歧义身份字段会拒绝。报告展示上限为 200 个问题和匹配记录，完整计数仍然保留。

请使用涵盖预期旧档案的完整快照：本工具无法发现已经不在旧快照里的剧集，也不会验证线上
重定向、音频内容一致性或托管可用性。详细安装、示例、测试和边界见 [英文说明](README.md)。

卸载使用 `python -m pip uninstall podcast-move-check`，再按需删除独立虚拟环境、`.demo` 和
自己保存的快照。工具不保存凭据或安装服务。代码及原创合成示例采用 MIT 许可证。
